    Further reading

    Sources on the Naked Objects pattern, the frameworks and standards it uses, and the domain-driven design ideas underneath it.

    Naked Objects and model-driven UI

    SourceWhy read it
    Naked Objects, Richard Pawson & Robert Matthews (Wiley, 2002)The original book on the pattern: the motivation, principles and case studies.
    Naked Objects, Richard Pawson, PhD thesis (Trinity College Dublin, 2004)The formal treatment, including the empirical case for the approach.
    Apache Causeway documentation (causeway.apache.org)The most complete working implementation: annotations, supporting methods, layouts, view models, security.
    Restful Objects specification, Dan HaywoodA standard REST API for domain objects; worth reading even if you build your own.
    Domain-Driven Design Using Naked Objects, Dan Haywood (Pragmatic Bookshelf, 2009)Combines the two ideas in one book, with a worked example.

    Standards and libraries

    • JSON Schema (json-schema.org): the specification and the "Understanding JSON Schema" guide.
    • JSON Forms (jsonforms.io): data schema + UI schema renderers for React, Angular and Vue.
    • react-jsonschema-form (rjsf-team on GitHub): schema-driven forms for React.
    • victools jsonschema-generator: JSON Schema from Java classes, with Jakarta Validation and Jackson modules.
    • Jakarta Bean Validation (Hibernate Validator is the reference implementation): constraint annotations.
    • RFC 9457: Problem Details for HTTP APIs.
    • Ajv: fast JSON Schema validation in JavaScript, for client-side checks.

    Domain-driven design background

    • Domain-Driven Design, Eric Evans (Addison-Wesley, 2003): the source of ubiquitous language, entities, value objects and aggregates.
    • Domain-Driven Design Distilled, Vaughn Vernon (2016): a short overview.
    • Learning Domain-Driven Design, Vlad Khononov (O'Reilly, 2021): a modern, approachable introduction.
    • Domain Modeling Made Functional, Scott Wlaschin (2018): excellent on value objects and making invalid states impossible.
    • "Anemic Domain Model", Martin Fowler (martinfowler.com): why objects need behaviour.

    Try it yourself

    1. Pick a small domain you know: a book club, a sports league, a home inventory.
    2. Write three POJOs with annotations from Java annotations, including at least one action with a disableX() rule.
    3. Build the introspector and serve GET /api/meta/{type}. Look at the JSON.
    4. Render one generic ObjectView (see Rendering).
    5. Add a fourth class and watch it appear in the UI with no frontend changes. That's the moment the idea clicks.
