    Start here

    A working Spring Boot + Vue template built the domain-driven way, with the reasoning behind every choice so you can make your own.

    What this repository is

    This repo has two parts that go together:

    1. A small working app: a shop with two bounded contexts (Catalog and Ordering). It has a Spring Boot 2.7 backend (Java 11, JPA/Hibernate 5, Flyway, H2 or PostgreSQL) and a Vue 3 + TypeScript frontend. It is small enough to read in an afternoon but uses every pattern you'll need in a real domain-driven app: aggregates, value objects, repositories, domain events, an anti-corruption layer, and architecture tests.
    2. This guide: what DDD is, which architecture choices you have, which ones the template makes and why, and how to adapt it for your own app.
    How to use it

    Read DB to screen first. It traces one click from the Vue button down to the SQL row and back, which ties all the other chapters together. Then read the concept chapters in order, keeping the code open next to the guide. Every pattern links to the class that implements it.

    Read the diagram from left to right. The browser only ever sees JSON. Each bounded context is a vertical slice with four layers. Dependencies point inward toward the domain. The two contexts talk to each other through only two narrow, deliberate channels.

    Run it in two minutes

    Shell
    # Terminal 1 — backend on :8080 (in-memory H2, seeded with demo products)
cd backend
./mvnw spring-boot:run

# Terminal 2 — frontend on :5173 (proxies /api to :8080)
cd frontend
npm install
npm run dev

    Open http://localhost:5173. Other useful URLs:

    URLWhat
    http://localhost:8080/swagger-ui.htmlInteractive OpenAPI docs for every endpoint
    http://localhost:8080/h2-consoleBrowse the database (JDBC URL jdbc:h2:mem:shop, user sa, empty password)
    http://localhost:8080/actuator/healthHealth check

    To use PostgreSQL instead, run docker compose up -d at the repo root, then ./mvnw spring-boot:run -Dspring-boot.run.profiles=postgres.

    Things to try in the UI

    • Start an order and click Place order with no lines. The domain rule "Cannot place an empty order" comes back as an error message.
    • Order 5 sticker packs (only 2 are in stock) and place the order. The Catalog context rejects the reservation, and the whole placement rolls back, so the order stays DRAFT.
    • Place an order, check stock in the Catalog, then cancel the order. The stock comes back through an OrderCancelled event.
    • Change a product's price after ordering it. The order keeps the old price, because order lines hold a snapshot.

    Why Spring Boot 2.7?

    The project targets Java 11. Spring Boot 3 requires Java 17, so this template uses Spring Boot 2.7, the last line that supports Java 11. That means javax.* imports (not jakarta.*) and Hibernate 5.6. Java 11 has no records, so immutable value classes use Lombok's @Value. Open-source support for Boot 2.7 has ended, so plan to move to Java 17+ and Boot 3 when your platform allows. The decision log lists exactly what changes.

    Editing this guide

    The guide pages are generated, so you can add your own project's decisions to them. Chapter sources are HTML fragments in docs/_chapters/. Code blocks inside them use triple-backtick fences, and the build escapes them for you. To rebuild:

    Shell
    python3 docs/build.py     # regenerates docs/*.html and the search index
open docs/index.html      # plain files; no server needed

    To add a page, create docs/_chapters/my-page.html with a title:/lede: front-matter block, add it to CHAPTERS in build.py, and rebuild.
