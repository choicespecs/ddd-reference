    Reference

    Glossary

    Every term used in this guide, with a short definition and a link to where it's explained.

    A – G

    Action
    A business operation on a domain object, exposed in the UI as a button and in the API as an invokable endpoint. →
    Aggregate
    A cluster of objects that changes as one unit, with a single root; in the UI, one page with nested children. →
    Aggregate root
    The entity in an aggregate that outside code and the UI interact with; gets its own page and URL.
    Anemic model
    Domain objects with data but no behaviour; produces a UI that is just a field editor. →
    Apache Causeway
    A Java framework implementing the Naked Objects pattern (formerly Apache Isis). →
    Bean Validation
    The Jakarta standard for constraint annotations (@NotNull, @Size, …); a ready-made source of metadata.
    Domain object
    A class that represents a business concept with its data, rules and behaviour, usually a POJO.
    Domain-driven design (DDD)
    An approach to software that puts a rich, shared model of the business at its centre (Eric Evans, 2003). →
    Entity
    An object with a lasting identity; gets its own page and is referenced by link. →

    I – P

    Instance representation
    The JSON for one object right now: values plus dynamic member state (hidden, disabled reasons). →
    Introspection
    Reading a class's structure at runtime with reflection to build its metamodel. →
    JSON Schema
    A standard vocabulary for describing JSON data (types, required fields, constraints). →
    Layout file
    A per-type file that arranges members into columns and groups, separate from the domain class. →
    Member
    A property, collection or action of a domain object.
    Metamodel
    A serialisable description of domain types and their members, consumed by the renderer and the API. →
    Naked Objects
    The pattern in which domain objects are exposed directly to users through a generated UI (Richard Pawson). →
    POJO
    Plain Old Java Object: a class with no required framework base class or interface.
    Problem+json
    The RFC 9457 format for HTTP API errors; lets a generic UI place errors on the right field. →

    R – Z

    Reference
    A property that points to another entity; rendered as a link plus a lookup.
    Restful Objects
    A specification for exposing domain objects over a generic REST API (Dan Haywood). →
    See it, use it, do it
    The order of checks for any member: visible (hide), usable (disable), valid (validate). →
    Spec registry
    The startup-built map of type name → ObjectSpec; doubles as the allowlist. →
    Supporting method
    A convention-named method (hideX, disableX, validateX, choicesNX, defaultNX) that governs a member. →
    Title
    The human-readable name of an object, used in headings, links and lookups.
    UI schema
    A JSON document describing layout and widgets for a data schema. →
    Ubiquitous language
    The shared vocabulary of experts and developers; here, also the labels in the UI. →
    Value object
    An immutable object defined by its attributes; rendered as a widget. →
    View model
    A non-persisted POJO built for a particular screen, rendered by the same machinery. →
    Widget registry
    The client-side map from kind or value type to a UI component. →
