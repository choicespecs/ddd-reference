    Security, config & deployment

    What the template leaves out on purpose, and how to add it — authentication, authorization, configuration per environment, packaging, and serving the Vue app.

    Security: what to add first

    The template has no authentication

    Every endpoint is open, which is fine for learning. Add the following before anything is reachable from a network you don't control.

    There are two common setups for a Vue SPA + Spring Boot API:

    A. Backend-for-Frontend (session cookie)B. SPA holds a JWT (bearer token)
    FlowSpring Boot does the OAuth2/OIDC login (oauth2Login) and keeps tokens server-side. The browser gets an HttpOnly session cookie.Vue logs in with an OIDC library (PKCE), stores the access token, and sends Authorization: Bearer …
    Spring configspring-boot-starter-oauth2-clientspring-boot-starter-oauth2-resource-server
    Token exposure to JSNone (more secure)Token in memory, so XSS can steal it
    CSRF protectionRequired (cookie auth)Not needed
    Works for other clients (mobile)Needs a separate resource-server chainYes
    Recommended whenSame-origin SPA; current OAuth best practice for browser appsThe API is shared by many clients

    The identity provider is a generic subdomain, so buy it rather than build it: Keycloak (self-hosted), Okta/Auth0, Microsoft Entra ID, AWS Cognito.

    Example: resource server (JWT)

    XML
    <dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-oauth2-resource-server</artifactId>
</dependency>
    YAML
    spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://login.example.com/realms/shop   # Keycloak realm, Entra tenant, etc.
    Java
    @Configuration
@EnableMethodSecurity
class SecurityConfig {
    @Bean
    SecurityFilterChain api(HttpSecurity http) throws Exception {
        return http
            .authorizeHttpRequests(auth -> auth
                .antMatchers("/actuator/health", "/v3/api-docs/**", "/swagger-ui/**").permitAll()
                .antMatchers(HttpMethod.GET, "/api/products/**").permitAll()
                .antMatchers("/api/products/**").hasRole("CATALOG_ADMIN")
                .antMatchers("/api/**").authenticated()   // Spring Security 6 renamed these to requestMatchers(...)
                .anyRequest().permitAll())                       // static Vue files
            .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults()))
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .csrf(csrf -> csrf.disable())                        // OK only for stateless bearer-token APIs
            .build();
    }
}

    Authorization in a DDD codebase

    Put coarse rules ("must be logged in", "must be an admin") in the security config. Put fine-grained rules ("only the customer who owns the order may cancel it") in the application layer, through a port, so they stay testable without Spring Security:

    Java
    public interface CurrentUser {
    String email();
    boolean hasRole(String role);
}

public OrderView cancel(UUID orderId) {
    Order order = load(orderId);
    if (!order.getCustomerEmail().getValue().equals(currentUser.email()) && !currentUser.hasRole("SUPPORT"))
        throw new AccessDeniedException("Not your order");
    order.cancel(clock);
    return saveAndPublish(order);
}
    Java
    // Adapter in infrastructure
@Component
class SpringSecurityCurrentUser implements CurrentUser {
    public String email() {
        Jwt jwt = (Jwt) SecurityContextHolder.getContext().getAuthentication().getPrincipal();
        return jwt.getClaimAsString("email");
    }
    public boolean hasRole(String role) { … }
}

    If a permission is really a business rule (for example, "orders over $10,000 need a manager's approval"), model it in the domain: order.approve(Approver approver).

    Security checklist

    • ☐ Authentication on every /api/** endpoint that isn't intentionally public
    • ☐ Authorization on the resource itself (ownership checks), not just on the role
    • ☐ Request DTOs whitelist the fields a client may set. Never bind entities.
    • ☐ The problem+json detail never contains stack traces or SQL (the template sets server.error.include-message: always for the domain messages; keep include-stacktrace: never)
    • ☐ CORS allow-list from configuration, never * together with credentials
    • ☐ Secrets from environment variables or a vault, never committed
    • ☐ Dependency scanning (./mvnw org.owasp:dependency-check-maven:check, npm audit, Dependabot)
    • ☐ Actuator: expose only health/info publicly
    • ☐ Security headers (CSP, HSTS) from Spring Security or the reverse proxy

    Configuration per environment

    Text
    backend/src/main/resources/
├── application.yml             defaults (local dev: H2)
├── application-postgres.yml    local Postgres via docker compose
├── application-test.yml        (add) test overrides
└── application-prod.yml        (add) production — values come from env vars
    YAML
    # application-prod.yml
spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USER}
    password: ${DB_PASSWORD}
  h2.console.enabled: false
  jpa.show-sql: false
app:
  cors:
    allowed-origins: ${ALLOWED_ORIGINS:https://shop.example.com}
server:
  error:
    include-stacktrace: never

    Activate it with SPRING_PROFILES_ACTIVE=prod. Any property can be overridden with an environment variable using relaxed binding: spring.datasource.url → SPRING_DATASOURCE_URL.

    Typed configuration

    Java
    // Immutable, constructor-bound properties (Spring Boot 2.2+)
@ConfigurationProperties(prefix = "app.ordering")
@ConstructorBinding                      // Boot 2.x needs this; Boot 3 infers it
@Value                                   // Lombok: final fields + getters
public class OrderingProperties {
    int maxLinesPerOrder;
    Duration draftExpiry;
}

// enable with @EnableConfigurationProperties(OrderingProperties.class) or @ConfigurationPropertiesScan

    Note that business limits like MAX_LINES are constants in the domain in the template. Move them to configuration only if the business wants to change them without a release. When you do, pass the value into the domain method rather than injecting Spring config into entities.

    Serving the Vue app from Spring Boot

    To ship a single JAR, copy the Vue build into Spring Boot's static resources and forward unknown routes to index.html so the Vue router can handle deep links.

    XML
    <!-- backend/pom.xml: build the frontend during `mvn package` -->
<plugin>
  <groupId>com.github.eirslett</groupId>
  <artifactId>frontend-maven-plugin</artifactId>
  <version>1.15.1</version>
  <configuration>
    <workingDirectory>../frontend</workingDirectory>
    <nodeVersion>v22.12.0</nodeVersion>
  </configuration>
  <executions>
    <execution><id>install-node</id><goals><goal>install-node-and-npm</goal></goals></execution>
    <execution><id>npm-ci</id><goals><goal>npm</goal></goals><configuration><arguments>ci</arguments></configuration></execution>
    <execution><id>npm-build</id><goals><goal>npm</goal></goals><configuration><arguments>run build</arguments></configuration></execution>
  </executions>
</plugin>
<plugin>
  <artifactId>maven-resources-plugin</artifactId>
  <executions>
    <execution>
      <id>copy-frontend</id>
      <phase>process-resources</phase>
      <goals><goal>copy-resources</goal></goals>
      <configuration>
        <outputDirectory>${project.build.outputDirectory}/static</outputDirectory>
        <resources><resource><directory>../frontend/dist</directory></resource></resources>
      </configuration>
    </execution>
  </executions>
</plugin>
    Java
    // SPA fallback: any non-API, non-file path → index.html
@Controller
class SpaForwardingController {
    @GetMapping({"/", "/products/**", "/orders/**"})
    String forward() {
        return "forward:/index.html";
    }
}

    Docker

    Text
    # Dockerfile (repo root) — multi-stage: build frontend, build backend, slim runtime
FROM node:22-alpine AS web
WORKDIR /web
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ ./
RUN npm run build

FROM eclipse-temurin:11-jdk AS api
WORKDIR /src
COPY backend/ ./
COPY --from=web /web/dist ./src/main/resources/static
RUN ./mvnw -q -DskipTests package

FROM eclipse-temurin:11-jre
WORKDIR /app
COPY --from=api /src/target/*.jar app.jar
USER 1000
EXPOSE 8080
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75", "-jar", "/app/app.jar"]

    An alternative that needs no Dockerfile is ./mvnw spring-boot:build-image, which produces an OCI image using Cloud Native Buildpacks.

    Observability

    • Health/readiness: /actuator/health, plus management.endpoint.health.probes.enabled=true for Kubernetes liveness and readiness probes.
    • Metrics: add micrometer-registry-prometheus. Record business metrics too, e.g. meterRegistry.counter("orders.placed").increment() in an OrderPlaced listener.
    • Tracing: micrometer-tracing-bridge-otel + an OTLP exporter.
    • Logging: structured JSON logs (on Boot 2.7, add logstash-logback-encoder and a logback-spring.xml; Boot 3.4+ has logging.structured.format.console=ecs built in). Log domain events at INFO level, because they make an excellent audit trail.

    CI pipeline sketch

    YAML
    # .github/workflows/ci.yml
name: ci
on: [push, pull_request]
jobs:
  backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '11', cache: maven }
      - run: cd backend && ./mvnw -B verify
  frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22', cache: npm, cache-dependency-path: frontend/package-lock.json }
      - run: cd frontend && npm ci && npm run build
