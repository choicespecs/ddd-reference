--- title: The running example lede: Fieldhouse is a fictional company that sells tickets for live events. Here are its domain objects, and the UI that is generated from them with no hand-written screens. ---

The domain objects

Back-office staff at Fieldhouse set up events, define price tiers and manage holds on seats. The model has four main classes and a few value objects:

```mermaid classDiagram class Event { EventId id String name Venue venue LocalDateTime onSaleAt EventStatus status List~PriceTier~ tiers publish() addTier(name, price, capacity) cancel(reason) } class PriceTier { String name Money price int capacity } class Venue { VenueId id String name String city } class Hold { HoldId id EmailAddress buyer int seats Instant expiresAt HoldStatus status release() } Event "1" *-- "many" PriceTier : owns Event --> Venue : refers to Hold --> Event : refers to ```

The Event POJO

This is the whole definition of Event. The annotations are described in Java annotations. Everything else is plain Java.

```java @DomainObject(plural = "Events", title = "name") public class Event { @Property(order = 1) @NotBlank @Size(max = 120) private String name; @Property(order = 2) @NotNull private Venue venue; // reference to another object → link + lookup @Property(order = 3, label = "On-sale opens") @NotNull @Future private LocalDateTime onSaleAt; // → date-time picker @Property(order = 4, editable = false) private EventStatus status = EventStatus.DRAFT; // enum → badge (read-only) @Collection(order = 5, label = "Price tiers") private final List tiers = new ArrayList<>(); // → table @Action(order = 1) public void publish() { status = EventStatus.ON_SALE; } public String disablePublish() { // convention: disable if (status != EventStatus.DRAFT) return "Only draft events can be published"; if (tiers.isEmpty()) return "Add at least one price tier first"; return null; // null = enabled } @Action(order = 2, label = "Add price tier") public PriceTier addTier(@NotBlank String name, @NotNull Money price, @Min(1) int capacity) { var tier = new PriceTier(name, price, capacity); tiers.add(tier); return tier; } @Action(order = 3, confirm = "Cancel this event? Buyers will be refunded.") public void cancel(@NotBlank @Size(max = 500) String reason) { status = EventStatus.CANCELLED; } public boolean hideCancel() { return status == EventStatus.CANCELLED; } // convention: hide } ```

The same object as JSON metadata

If you take the JSON path instead, the same object is described like this (abridged). The renderer produces the same screen.

```json { "type": "Event", "plural": "Events", "titleProperty": "name", "schema": { "type": "object", "required": ["name", "venue", "onSaleAt"], "properties": { "name": { "type": "string", "maxLength": 120, "title": "Name" }, "venue": { "type": "string", "format": "ref:Venue", "title": "Venue" }, "onSaleAt": { "type": "string", "format": "date-time", "title": "On-sale opens" }, "status": { "type": "string", "enum": ["DRAFT", "ON_SALE", "CANCELLED"], "readOnly": true }, "tiers": { "type": "array", "items": { "$ref": "#/$defs/PriceTier" }, "title": "Price tiers" } } }, "actions": [ { "id": "publish", "label": "Publish" }, { "id": "addTier", "label": "Add price tier", "parameters": { "$ref": "#/$defs/AddTierParams" } }, { "id": "cancel", "label": "Cancel", "confirm": "Cancel this event? Buyers will be refunded." } ] } ```
Adding a new object

To add a Promotion to the system, write the Promotion class. It gets a list page, a detail page, forms, actions and API endpoints automatically. That's the promise of this approach, and the rest of the guide shows how it works.
