API cookbook (curl)

Start the backend (cd backend && ./mvnw spring-boot:run), then:

```bash # --- Catalog --------------------------------------------------------------- curl -s localhost:8080/api/products | jq curl -s -X POST localhost:8080/api/products -H 'Content-Type: application/json' -d '{ "sku": "BOOK-0042", "name": "Patterns of Enterprise Application Architecture", "description": "Fowler", "price": 59.95, "currency": "USD", "initialStock": 5 }' | jq P=11111111-1111-1111-1111-000000000001 curl -s -X PUT localhost:8080/api/products/$P/price -H 'Content-Type: application/json' -d '{"price": 49.00, "currency": "USD"}' | jq curl -s -X POST localhost:8080/api/products/$P/stock -H 'Content-Type: application/json' -d '{"quantity": 10}' | jq # --- Ordering -------------------------------------------------------------- O=$(curl -s -X POST localhost:8080/api/orders -H 'Content-Type: application/json' \ -d '{"customerEmail":"ada@example.com"}' | jq -r .id) curl -s -X POST localhost:8080/api/orders/$O/lines -H 'Content-Type: application/json' \ -d "{\"productId\":\"$P\",\"quantity\":2}" | jq '.lines, .total' curl -s -X PUT localhost:8080/api/orders/$O/lines/$P -H 'Content-Type: application/json' -d '{"quantity":3}' | jq .total curl -s -X POST localhost:8080/api/orders/$O/place | jq .status # "PLACED" curl -s localhost:8080/api/products/$P | jq .stockOnHand # reduced by 3 curl -s -X POST localhost:8080/api/orders/$O/cancel | jq .status # "CANCELLED" curl -s localhost:8080/api/products/$P | jq .stockOnHand # restored # --- Rule violations (all return application/problem+json) ----------------- E=$(curl -s -X POST localhost:8080/api/orders -H 'Content-Type: application/json' -d '{"customerEmail":"x@y.co"}' | jq -r .id) curl -s -X POST localhost:8080/api/orders/$E/place | jq # 409 "Cannot place an empty order" curl -s -X POST localhost:8080/api/orders -H 'Content-Type: application/json' -d '{"customerEmail":"nope"}' | jq # 400 curl -s localhost:8080/api/orders/00000000-0000-0000-0000-000000000000 | jq # 404 ```

Peek at the database

Open http://localhost:8080/h2-console (JDBC URL jdbc:h2:mem:shop, user sa) and try:

```sql SELECT sku, name, stock_on_hand, version FROM catalog_product ORDER BY sku; SELECT o.status, o.customer_email, l.product_name, l.quantity, l.unit_price_amount FROM ordering_order o JOIN ordering_order_line l ON l.order_id = o.id ORDER BY o.created_at DESC; SELECT * FROM "flyway_schema_history"; ```

Watch version go up each time you change a product or order. That's optimistic locking at work.

Exercises to extend the template

Each exercise exercises a specific pattern. They're ordered roughly by difficulty.

#ExercisePatterns practiced
1Add Product.rename() and an endpoint + UI to edit namesBehaviour method, thin controller, Vue form
2Add a Quantity value object (1–99) and use it in OrderLineValue object, embeddable or converter
3Add allowedActions to OrderView; drive the Vue buttons from itRead model design, UI without duplicated rules
4Send a (logged) confirmation "email" with an AFTER_COMMIT listener on OrderPlacedTransaction phases, side effects
5Add a Promotion concept: percentage off for a SKU between two datesDomain service / policy, DateRange VO
6Add an OrderSummary JPQL projection for the order list (no aggregate loading)CQRS-lite read side
7Add a Customer context with registration; Ordering references CustomerIdNew bounded context, ACL, ArchUnit rule updates
8Add Spring Security (resource server) + Keycloak in docker-compose; only owners can cancelCurrentUser port, authorization in the app layer
9Switch stock reservation to AFTER_COMMIT + outbox with a PENDING_STOCK statusEventual consistency, saga
10Replace H2 with Testcontainers PostgreSQL in all integration testsTest fidelity
