--- title: Repositories & factories lede: Repositories give the domain the illusion of an in-memory collection of aggregates. Factories hide complex creation. Both keep lifecycle concerns out of the model. ---

Repositories

Repository
An abstraction that gives access to aggregates as if they were in an in-memory collection: add one, find one by id, and (for some styles) save one. It hides how and where they're stored.

Rules of thumb

  • One repository per aggregate root, never per child entity. You load and save the whole aggregate.
  • The interface lives in the domain and is expressed in domain types. The implementation lives in infrastructure. This is dependency inversion, the port in ports & adapters.
  • Collection-like API, not a generic DAO: add, get, findBy… for real domain questions. Avoid exposing update(table, column, value).
  • No business logic. The repository stores and retrieves. The aggregate decides.
  • Don't use them for reporting. Screens and reports that join across aggregates should use dedicated read models, not repositories.
```java // domain layer: a port public interface HoldRepository { void add(Hold hold); Hold get(HoldId id); // throws HoldNotFound List activeExpiringBefore(Instant cutoff); // a real domain question int seatsHeldOrOwnedBy(BuyerId buyer, EventId event); void save(Hold hold); // or rely on unit-of-work tracking } ``` ```java // infrastructure layer: an adapter (e.g. JDBC/ORM/document store) class SqlHoldRepository implements HoldRepository { private final HoldTable table; // persistence model, framework-specific private final HoldMapper mapper; // domain ↔ persistence translation public Hold get(HoldId id) { return table.findById(id.value()).map(mapper::toDomain) .orElseThrow(() -> new HoldNotFound(id)); } public void save(Hold hold) { table.save(mapper.toRow(hold)); // version column → optimistic lock } // … } ```

Collection-oriented vs. persistence-oriented

StyleHow it worksFits
Collection-orientedadd once. Changes are tracked and flushed by a unit of work (ORM dirty checking)Hibernate/JPA, Entity Framework
Persistence-orientedExplicit save(aggregate) after every changeDocument stores, key-value stores, hand-written SQL, event stores

Either is fine. Explicit save is easier to reason about and to swap out, and it makes the one-aggregate-per-transaction rule visible in the code.

In-memory fakes

Because the repository is an interface in domain terms, a HashMap-backed fake makes application-layer tests fast and readable. Run the same contract test suite against the fake and the real adapter so they can't drift apart (see Testing).

Factories

Factory
Anything whose job is to create a valid aggregate or complex value: a static method, a dedicated class, or a method on another aggregate. It ensures that objects are born satisfying their invariants.

Forms a factory can take

```java // 1. Named static constructor on the aggregate (the most common) public static Hold place(BuyerId buyer, EventId event, SeatSelection seats, Instant now) { var hold = new Hold(HoldId.newId(), buyer, event, seats, now.plus(HOLD_DURATION)); hold.record(new HoldPlaced(hold.id, buyer, event, seats, now)); return hold; } // 2. Factory method on another aggregate: expresses the domain relationship Order order = hold.toOrder(payment); // "an order is created from a hold" // 3. Dedicated factory class when creation needs collaborators or policies public class PricedSelectionFactory { private final PriceTierPolicy tiers; public PricedSelection price(EventId event, SeatSelection seats, PromoCode promo) { … } } ```

Creation vs. reconstitution

Creating something new enforces rules and records events. Reconstituting an existing aggregate from storage must not repeat those checks or re-raise events. A hold that's already expired must still be loadable. Keep the two paths separate: a public factory for creation, and a package-private constructor or mapper for reconstitution.

When you don't need a factory

If a plain constructor with value-object parameters can create a valid object, use it. Add factories when creation has a domain name ("place a hold"), needs to raise an event, or involves logic that doesn't belong in the constructor.
