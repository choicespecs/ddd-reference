Domain unit tests

No Spring, no mocks, no database. Build the aggregate, call a method, and assert on the state and the events raised:

```java class OrderTest { private final Clock clock = Clock.fixed(Instant.parse("2026-01-01T10:00:00Z"), ZoneOffset.UTC); @Test void placing_changes_status_and_raises_event() { Order order = Order.startDraft(new CustomerEmail("ada@example.com"), clock); order.addLine(book, "DDD", Money.of("50.00", "USD"), 2); order.place(clock); assertThat(order.getStatus()).isEqualTo(OrderStatus.PLACED); assertThat(order.getPlacedAt()).isEqualTo(clock.instant()); // deterministic thanks to Clock assertThat(order.peekDomainEvents()) .singleElement() .isInstanceOfSatisfying(OrderPlaced.class, e -> assertThat(e.total()).isEqualTo(Money.of("100.00", "USD"))); } @Test void placed_order_is_frozen() { … assertThatThrownBy(() -> order.addLine(mug, "Mug", Money.of("1.00", "USD"), 1)) .isInstanceOf(DomainException.class) .hasMessageContaining("PLACED"); } } ```

Tips:

  • Name tests as rules: shipped_order_cannot_be_cancelled. The test list then reads like a spec.
  • Inject time. Pass a Clock instead of calling Instant.now(), and you get deterministic assertions.
  • Group with @Nested by behaviour (Placing, Cancelling).
  • Use test data builders once construction gets noisy: anOrder().withLine(book, 2).placed().build().

Value object tests

```java class MoneyTest { @Test void normalizes_scale() { assertThat(Money.of("5", "USD")).isEqualTo(Money.of("5.00", "USD")); } @Test void rejects_negative() { assertThatThrownBy(() -> Money.of("-1", "USD")).isInstanceOf(DomainException.class); } @Test void rejects_unknown_currency(){ assertThatThrownBy(() -> Money.of("1", "XYZ")).isInstanceOf(IllegalArgumentException.class); } @Test void cannot_add_mixed_currency(){ assertThatThrownBy(() -> Money.of("1","USD").plus(Money.of("1","EUR"))).isInstanceOf(DomainException.class); } } ```
