Security: what to add first

The template has no authentication

Every endpoint is open, which is fine for learning. Add the following before anything is reachable from a network you don't control.

There are two common setups for a Vue SPA + Spring Boot API:

A. Backend-for-Frontend (session cookie)B. SPA holds a JWT (bearer token)
FlowSpring Boot does the OAuth2/OIDC login (oauth2Login) and keeps tokens server-side. The browser gets an HttpOnly session cookie.Vue logs in with an OIDC library (PKCE), stores the access token, and sends Authorization: Bearer …

The identity provider is a generic subdomain, so buy it rather than build it: Keycloak (self-hosted), Okta/Auth0, Microsoft Entra ID, AWS Cognito.

Example: resource server (JWT)

```xml org.springframework.boot spring-boot-starter-oauth2-resource-server ``` ```yaml spring: security: oauth2: resourceserver: jwt: issuer-uri: https://login.example.com/realms/shop # Keycloak realm, Entra tenant, etc. ``` ```java @Configuration @EnableMethodSecurity class SecurityConfig { @Bean SecurityFilterChain api(HttpSecurity http) throws Exception { return http .authorizeHttpRequests(auth -> auth .requestMatchers("/actuator/health", "/v3/api-docs/**", "/swagger-ui/**").permitAll() .requestMatchers(HttpMethod.GET, "/api/products/**").permitAll() .requestMatchers("/api/products/**").hasRole("CATALOG_ADMIN") .requestMatchers("/api/**").authenticated() .anyRequest().permitAll()) // static Vue files .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults())) .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS)) .csrf(csrf -> csrf.disable()) // OK only for stateless bearer-token APIs .build(); } } ```

Authorization in a DDD codebase

Put coarse rules ("must be logged in", "must be an admin") in the security config. Put fine-grained rules ("only the customer who owns the order may cancel it") in the application layer, through a port, so they stay testable without Spring Security:

```java public interface CurrentUser { String email(); boolean hasRole(String role); } public OrderView cancel(UUID orderId) { Order order = load(orderId); if (!order.customerEmail().value().equals(currentUser.email()) && !currentUser.hasRole("SUPPORT")) throw new AccessDeniedException("Not your order"); order.cancel(clock); return saveAndPublish(order); } ``` ```java // Adapter in infrastructure @Component class SpringSecurityCurrentUser implements CurrentUser { public String email() { Jwt jwt = (Jwt) SecurityContextHolder.getContext().getAuthentication().getPrincipal(); return jwt.getClaimAsString("email"); } public boolean hasRole(String role) { … } } ```

If a permission is really a business rule (for example, "orders over $10,000 need a manager's approval"), model it in the domain: order.approve(Approver approver).

Security checklist

  • ☐ Authentication on every /api/** endpoint that isn't intentionally public
  • ☐ Authorization on the resource itself (ownership checks), not just on the role
  • ☐ Request DTOs whitelist the fields a client may set. Never bind entities.
  • ☐ ProblemDetail detail never contains stack traces or SQL (the template sets server.error.include-message: always for the domain messages; keep include-stacktrace: never)
  • ☐ CORS allow-list from configuration, never * together with credentials
  • ☐ Secrets from environment variables or a vault, never committed
  • ☐ Dependency scanning (./mvnw org.owasp:dependency-check-maven:check, npm audit, Dependabot)
  • ☐ Actuator: expose only health/info publicly
  • ☐ Security headers (CSP, HSTS) from Spring Security or the reverse proxy

Configuration per environment

```text backend/src/main/resources/ ├── application.yml defaults (local dev: H2) ├── application-postgres.yml local Postgres via docker compose ├── application-test.yml (add) test overrides └── application-prod.yml (add) production — values come from env vars ``` ```yaml # application-prod.yml spring: datasource: url: ${DB_URL} username: ${DB_USER} password: ${DB_PASSWORD} h2.console.enabled: false jpa.show-sql: false app: cors: allowed-origins: ${ALLOWED_ORIGINS:https://shop.example.com} server: error: include-stacktrace: never ```

Activate it with SPRING_PROFILES_ACTIVE=prod. Any property can be overridden with an environment variable using relaxed binding: spring.datasource.url → SPRING_DATASOURCE_URL.

Typed configuration

```java @ConfigurationProperties(prefix = "app.ordering") public record OrderingProperties(int maxLinesPerOrder, Duration draftExpiry) {} // enable with @EnableConfigurationProperties(OrderingProperties.class) or @ConfigurationPropertiesScan ```

Note that business limits like MAX_LINES are constants in the domain in the template. Move them to configuration only if the business wants to change them without a release. When you do, pass the value into the domain method rather than injecting Spring config into entities.

Building

```bash # Backend: runnable fat JAR cd backend && ./mvnw clean package java -jar target/shop-0.1.0-SNAPSHOT.jar # Frontend: static files cd frontend && npm ci && npm run build # → frontend/dist ```

Serving the Vue app from Spring Boot

To ship a single JAR, copy the Vue build into Spring Boot's static resources and forward unknown routes to index.html so the Vue router can handle deep links.

```xml com.github.eirslett frontend-maven-plugin 1.15.1 ../frontend v22.12.0 install-nodeinstall-node-and-npm npm-cinpmci npm-buildnpmrun build maven-resources-plugin copy-frontend process-resources copy-resources ${project.build.outputDirectory}/static ../frontend/dist ``` ```java // SPA fallback: any non-API, non-file path → index.html @Controller class SpaForwardingController { @GetMapping({"/", "/products/**", "/orders/**"}) String forward() { return "forward:/index.html"; } } ```

Docker

```text # Dockerfile (repo root) — multi-stage: build frontend, build backend, slim runtime FROM node:22-alpine AS web WORKDIR /web COPY frontend/package*.json ./ RUN npm ci COPY frontend/ ./ RUN npm run build FROM eclipse-temurin:17-jdk AS api WORKDIR /src COPY backend/ ./ COPY --from=web /web/dist ./src/main/resources/static RUN ./mvnw -q -DskipTests package FROM eclipse-temurin:17-jre WORKDIR /app COPY --from=api /src/target/*.jar app.jar USER 1000 EXPOSE 8080 ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75", "-jar", "/app/app.jar"] ```

An alternative that needs no Dockerfile is ./mvnw spring-boot:build-image, which produces an OCI image using Cloud Native Buildpacks.

Observability

  • Health/readiness: /actuator/health, plus management.endpoint.health.probes.enabled=true for Kubernetes liveness and readiness probes.
  • Metrics: add micrometer-registry-prometheus. Record business metrics too, e.g. meterRegistry.counter("orders.placed").increment() in an OrderPlaced listener.
  • Tracing: micrometer-tracing-bridge-otel + an OTLP exporter.
  • Logging: structured JSON logs (logging.structured.format.console=ecs in Boot 3.4+). Log domain events at INFO level, because they make an excellent audit trail.
